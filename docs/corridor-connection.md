# 한국 교실 + 일본 복도 연결

## 적용 결과

하나의 Three.js scene에서 두 모델을 동시에 로딩합니다. 텔레포트나 장면 전환 없이 교실 문을 통과해
복도로 이동하고 돌아올 수 있습니다. 기본 PC/VR 이동, 숙이기와 의자 빼기는 유지했습니다.

교실에서 복도를 바라볼 때 **왼쪽(앞, -Z) 문 / 오른쪽(뒤, +Z) 문**으로 구분합니다.
복도에서는 보는 방향이 반대이므로 시각적인 좌우는 반전되지만 문 이름과 독립 상태는 유지됩니다.

- PC: 가까이에서 해당 문을 바라보고 **E**.
- Meta Quest: 해당 문을 컨트롤러 광선으로 가리키고 **트리거**.
- 두 문은 각각 닫힌 상태로 시작하며 한 문을 조작해도 다른 문은 변하지 않습니다.
- 각 출입구의 패널 하나가 다른 패널 위로 미끄러져 약 0.83~0.84m가 개방됩니다.
- 문이 움직이면 충돌체도 함께 이동합니다. 닫힐 경로에 사용자가 있으면 닫기를 거부합니다.
- 문 자체에 가까이 다가가기 전 상호작용 범위는 2.5m입니다.

## 먼저 확인한 원본 구조

### 한국 교실

기존 모델 파일과 배율(28), 위치, 재질은 유지했습니다. 원본 문에는 갈색 목재 패널과 유리 창이 있고,
벽과 분리된 다음 네 개의 메시가 있습니다.

| 출입구 | 이동 패널 | 짝 패널 |
|---|---|---|
| 왼쪽(앞) | 노드 760 `polySurface4_standardSurface8_0` | 노드 762 `polySurface5_standardSurface8_0` |
| 오른쪽(뒤) | 노드 764 `polySurface6_standardSurface8_0` | 노드 766 `polySurface7_standardSurface8_0` |

네 메시를 복제하지 않고 원래 객체를 그대로 사용합니다. 기존 문 재질은 double-sided이므로
한 객체가 교실과 복도 양쪽에서 보입니다. 형태·크기·색상·UV·유리 설정을 변경하거나 신규 문을 만들지 않았습니다.
기존 한국 교실의 복도 쪽 벽과 중앙 기둥도 공유합니다.

### 일본 복도

원본은 세분화된 개별 문 노드가 없고 **Windows / Wall / Floor / Roof / Ladder의 다섯 메시**입니다.
복도 쪽 문과 장식은 Wall 메시 안에 합쳐져 있습니다. 복도 원본 Wall을 한국 교실 앞에 겹쳐 놓으면
한국 문을 열어도 이 Wall이 가로막게 됩니다. 충돌만 없애는 방식으로 해결하지 않았습니다.

## 크기와 배치

복도는 원본 루트 변환을 누적하면 미터 기준으로 사용할 수 있어 배율 **1**을 유지했습니다.

| 항목 | 적용 좌표 / 크기 |
|---|---|
| 교실 바닥 | 기존과 동일 Y=3.2m |
| 복도 바닥 | Y=3.2m (원본 FBX의 마이크로미터 수준 회전 오차는 보행 높이에서 정규화) |
| 복도 이동 | X=7.3220898586m, Y=3.2m, Z=0 |
| 복도 바닥 범위 | X=5.000~9.464m, Z=-11.640~11.626m |
| 복도 폭 / 길이 | 약 4.46m / 23.27m |
| 복도 벽 높이 | 약 3.35m; 조명/천장 부재 최저 약 2.90m |
| 원본 전체(양끝 계단 포함) | 약 4.67×3.35×37.00m |

교실 출입구가 X≈4.94~5.01m에 있으므로 복도 바닥의 시작을 X=5m에 맞췄습니다.
출입구의 좁은 문턱 보행면은 두 바닥에 걸쳐 있으며 높이 변화가 없습니다.
두 모델 모두 길이 방향이 Z이므로 복도를 추가 회전시키거나 비균등 스케일로 변형하지 않았습니다.

## 별도 수정본을 만든 부분

원본 보관 경로: `public/models/corridor/original/`

수정본 경로: **`public/models/corridor/connected/scene.gltf` + `connection.bin`**

수정은 `scripts/prepare-corridor.mjs`의 다각형 클리핑으로 재현합니다.

1. 원본 복도 Wall에서 **Z=-4.226616~4.226617m, 바닥부터 Y=2.94m**에 해당하는 부분을 실제로 제거합니다.
   한국 교실의 기존 벽과 두 문이 이 부분을 대체합니다. 문만 앞에 놓거나 투명 처리한 것이 아닙니다.
2. 위쪽의 복도 벽 띠는 유지합니다. 교실 벽과 복도 벽의 두께 차이는 상부와 양 끝의 얕은 벽 접합면
   세 장으로 닫았습니다. 원본 Wall 재질을 사용한 단순 벽 마감이며 새 문·문 패널·문 디자인은 없습니다.
3. 원본 양끝 계단 중 +Z 쪽 계단 부분은 수정본에서 제거하고, 기존 프로젝트의 하행 대피 계단과
   1층 출입구·운동장을 복도 +Z 끝으로 옮겨 연결했습니다. 반대쪽 원본 계단은 보존했습니다.
   기존 임시 복도의 바닥·천장·벽·충돌은 생성하지 않습니다.

Windows / Floor / Roof 메시의 primitive와 원본 버퍼, 재질 5개, 이미지 13개는 유지합니다.
잘린 면의 경계에서는 UV·법선·탄젠트를 보간하여 기존 텍스처를 유지합니다.
수정본은 원본 bin과 텍스처를 상대경로로 참조하므로 **original 폴더도 함께 배포**해야 합니다.
추가 텍스처 다운로드나 새로운 문 모델은 필요하지 않습니다.

현재 구조는 축에 정렬된 벽 구간을 정확히 절개할 수 있어 Blender 수정 없이 처리했습니다.
향후 벽이 곡면이거나 문틀·힌지가 완전히 일체화된 다른 모델로 교체되면 Blender에서 메시 분리,
Boolean 개구부, UV 유지 및 노멀 정리 후 별도 GLB로 export하는 편이 적절합니다.

## 충돌과 상호작용

- 교실 가구: 기존 삼각형 충돌 유지.
- 공유 교실 벽: 두 출입구를 제외한 벽/문 상부만 충돌.
- 문: 원본 패널에 연결된 이동 AABB, PC/VR 공통 사용.
- 복도 Wall: 수정된 실제 삼각형을 충돌에 사용해 잘린 부분에 보이지 않는 벽이 남지 않음.
- 창문 쪽: 원본 유리벽 영역의 충돌 유지.
- 바닥: 교실·문턱·복도 높이 모두 3.2m.
- 반대쪽 원본 계단: 실제 수평 디딤면을 보행면으로 등록.
- 옮긴 하행 계단·운동장: 시각 geometry와 동일한 강체 변환을 충돌 데이터에도 적용.

## 재생성과 검증

```sh
npm run prepare:corridor
npm test
npm run build
npm run dev
```

`docs/corridor-edit-report.json`은 실제 수정 노드와 잘라낸 범위를 기록합니다.
테스트는 두 문 독립 상태, 원본 문 네 개의 단일 재사용, 닫힌 문 차단, 양쪽 출입구 왕복과 바닥 높이,
열린 문 양쪽 시야, 복도 쪽 PC/VR 레이 선택, 대피 계단 및 운동장 왕복을 포함합니다.
원본 파일 보존 확인은 `docs/model-preservation.json`에 기록합니다.

브라우저에서 문을 열고 실제 복도로 걸어 나가는 동작과 기존 재질 표시를 확인했습니다.
실제 Quest는 연결되어 있지 않으므로 기기에서 컨트롤러 입력·프레임률 확인은 남아 있습니다.
복도 원본은 4K PBR 텍스처가 포함되어 용량 약 38MB이므로 Quest 최적화는 별도 파생 텍스처로 진행하는 것이 좋습니다.

## 후속 바닥 통일

연결용 파일의 원본 Floor 데이터는 보존하되 런타임에서는 교실 바닥 재질로 교체하고 원본 교실 UV를 연장합니다. 복도 바닥의 평면 오차와 경계만 정리하며 외곽·충돌을 유지합니다. [자세한 바닥 적용 기록](floor-continuity.md)을 참고하세요.
