# 학교 탐색 환경: 원인 분석과 수정

## 확인한 원인

### 층간 이동 차단

업로드된 통합 모델에는 외관 GLB의 계단과 실내 GLB의 계단이 동시에 남아 있었습니다. 남측 계단의 동일 위치 `(40.6, -40)`에서 외관 디딤판은 약 3.5414m, 실내 복제 디딤판은 약 3.6663m로, 약 12.5cm 차이가 났습니다. 실내 복제본에는 계단실을 가로지르는 층 바닥도 포함되어 있었습니다. 이전 통합 과정에서 외관 계단의 되돌아오는 구간 일부도 잘려 있어, 충돌만 끄는 방식으로 해결할 수 있는 상태가 아니었습니다.

- 두 계단실 내부의 중복 복제 구조를 절개해 제거했습니다.
- 처음 제공된 외관 원본 GLB에서 실제 계단·계단참·난간을 그대로 복원했습니다. 임의의 새 계단 모델을 만들지 않았습니다.
- 원래 디딤판과 계단참의 높이·범위로 보행 경사를 계산했습니다. 화면에 보이는 계단 메시와 텍스처는 원본 그대로입니다.
- 원본 계단 끝과 층 바닥 사이 약 9.4cm의 모델 이음새는 발의 지지 영역(10cm)을 검사해 건너갑니다. 넓은 구멍에 대체 바닥을 깔거나, 지지면 없는 곳으로 이동시키지 않습니다.

### 보행 높이와 카메라 흔들림

이전 바닥 판정은 현재 발높이 ±32cm 안에서 가장 높은 삼각형을 선택했습니다. 통합 모델에는 같은 층에 4mm 차이의 바닥이 있고, 일부 영역에는 다른 높이의 슬래브도 있어 경계에서 발높이가 튈 수 있었습니다. 계단에서는 실제 디딤판 높이만큼 카메라가 즉시 올라가는 처리였습니다.

- 현재 발높이에 가장 가까운 지지면을 우선합니다.
- 계단은 측정한 경사 지지면으로 연속 보행하며, 벽·난간·천장 충돌은 유지합니다.
- PC는 가상 보행의 수직 높이만 보간합니다. 마우스 시점과 VR 헤드셋의 실제 자세·회전은 필터링하지 않습니다.
- 남측·북측 계단 각각 1층→4층 및 4층→1층 연속 경로 검사를 통과했습니다. 2.5cm 보행 검사 단위의 발높이 변화 최댓값은 남측 약 1.98cm, 북측 약 1.23cm였습니다.

### 겹친 면과 Z-fighting

외관/실내 복제본 사이에서 법선과 위치가 일치하는 면을 검사했습니다. 한 면의 모든 점이 다른 면에서 6mm 안에 있고 투영 영역이 겹치는 경우, 겹친 부분만 다각형 차집합으로 잘라냈습니다. 고유한 경계와 UV는 보간해 유지합니다.

- 중복 영역과 겹친 외관 삼각형 1,653개의 영역을 정리했습니다. 겹친 면적 합계는 약 7,535.79m²입니다. 부분 겹침을 잘라 재삼각화하므로 최종 삼각형 수가 단순히 감소하지는 않습니다.
- depth test를 끄거나 모델 전체를 밀어 겹침을 감추지 않았습니다.
- 카메라 near/far를 0.05/200m에서 0.08/160m로 조정하고, 원본 이미지 변경 없이 anisotropic filtering을 적용했습니다.

### 계단의 잘못 겹친 패널과 문 상호작용

두 계단실의 실내 복제 패널·문틀·슬래브를 제거하고 외관 원본 계단 구조로 교체했습니다. 문 상호작용은 원본에서 분리된 교실 출입문 24곳만 유지합니다. 모든 문 상호작용 경계가 두 계단실과 교차하지 않는지도 검사합니다. 실제 교실 문짝은 복제하거나 새로 만들지 않았습니다.

### 태극기

태극기는 이미지 텍스처가 아니라 별도 흰 바탕·빨강·파랑·검정 문양과 액자 메시였습니다. 원본 노드 21871–21875만 제거했습니다. 바로 이웃한 게시물 노드 21870은 유지합니다.

## 렌더링 부하와 검증 한계

원본 학교는 약 520만 삼각형과 큰 텍스처를 포함합니다. 앱 내 미리보기의 동일 시작 시점에서 다음 카운터를 확인했습니다.

- 변경 전: 약 1,106 draw calls, 1,224,775 triangles/frame.
- 보수적 깊이 가림 검사 적용 후: 약 303–307 draw calls, 443,576–443,624 triangles/frame.

WebGL2가 현재 깊이 버퍼에 의해 완전히 가려졌다고 판정한 셀만 그리기를 생략합니다. 두 차례 확인 후 숨기고, 문이 움직이거나 카메라가 크게 이동하면 즉시 다시 표시합니다. 원본 메시·재질·텍스처를 변경하지 않습니다. 지원하지 않는 환경에서는 원래 렌더링으로 돌아가며, VR에서는 이 가림 최적화를 끄고 모든 원본 가시성을 복원합니다.

최종 단일 미리보기에서는 시작 화면과 PC 탐색 모두 약 **60 FPS**였습니다. PC 탐색의 CPU 시간은 약 9.9ms(이동 판정 8.3ms), 그리기를 제외한 대조 실험은 60 FPS / 0.2ms였습니다. 앞선 검증에서 관측한 13.6–15.7 FPS는 최종 상태에서 재현되지 않았으므로, 원인을 특정 브라우저 제한이나 GPU 문제로 단정하지 않습니다.

**이 측정이 모든 PC/Quest에서 목표 FPS를 보장한다는 뜻은 아닙니다.** 실제 프레임 속도와 GPU/브라우저 진단 결과는 별도 `browser-diagnostics.json`에 기록합니다. Quest 실기기와 외부 Chrome/Edge의 GPU 프로파일은 이 세션에서 검증하지 못했습니다. 남아 있는 프레임 저하가 있다면 실제 기기의 GPU 가속/프레임 타이밍을 확인해야 하며, 원본 자산 유지 조건 안에서 충분한 성능이 나오지 않는 경우에만 별도 LOD·텍스처 경량화 허용 여부를 결정해야 합니다. 이번 수정에서는 형상 단순화나 텍스처 축소를 하지 않았습니다.

## 보존 범위와 재현

- 사용자 원본 `school.glb`는 변경하지 않습니다.
- 정리된 파생 원본은 `repaired-source.glb`, 실행 파일은 `render.glb`입니다.
- 전체 재질 JSON과 82개 내장 이미지 바이트의 동일성을 검사합니다.
- 기존 재난 체험 `/legacy.html` 및 그 자산은 수정하지 않습니다.
- 두 계단의 상하행, 복도 연결, 닫힌/열린 문 충돌, PC/VR 대상 선택, VR 조이스틱 모의 입력, 카메라 수직 안정성, 태극기 제거 및 인접 물체 보존을 검사합니다.

생성 순서: `repair-model.mjs` → `build-navigation.mjs` → `prepare-collision.mjs` → `batch-model.mjs` → `npm test` → `npm run build`.
계단 복원에는 처음 제공된 외관 GLB가 필요합니다. 결과 웹/실행 앱에는 필요한 결과 자산이 모두 들어 있어 별도 원본 파일 경로가 필요하지 않습니다.
