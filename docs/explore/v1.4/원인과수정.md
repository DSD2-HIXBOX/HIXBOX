# 학교 탐색 1.4: 깊이 안정화와 낮 조명

## 확인한 원인

현재 자산의 4개 층 바닥을 격자로 조사했습니다. 바닥이 검출된 1,404개 표본 중 26개에 같은 높이의 복수 면이 있었습니다. 예를 들어 `(30.137, -26.729)`의 1층에는 `floor terrazzo`와 `[Wood Floor]1`이 모두 Y=2.699600m이고, `(40.137, -12.729)`의 3층에는 `stair_rail`과 `[Color M01]`이 모두 Y=8.799600m입니다. 같은 깊이에서 다른 재질이 경쟁할 수 있습니다. 반면 시작점 복도의 바닥과 하부 슬래브는 15cm 떨어져 있어, 그 지점의 문제를 겹친 바닥이라고 단정하지 않았습니다. 표본과 면의 재질·법선·위치는 depth-audit.json / floor-overlaps.json에 기록합니다.

이동 시 표면이 통째로 사라지는 현상은 깊이 충돌과 다릅니다. 비동기 GPU 가림 판정은 카메라 이동 중 이전 프레임의 결과를 사용하므로 가시성 전환을 만들 수 있습니다. 벽·바닥·천장·주요 구조재는 이 판정에서 제외하고 일반적인 시야 절두체와 거리 판정만 사용합니다. 가구 등에 대한 최적화는 유지합니다.

## 형상 보존 방식의 수정

GLB 삼각형을 삭제하거나 위치를 옮기지 않았습니다. 겹친 마감·바탕 면에 작은 렌더링 깊이 우선순위만 부여했습니다. Three.js polygonOffsetUnits를 사용하며 경사에 따라 과도하게 밀리지 않도록 polygonOffsetFactor는 0입니다. 목재 마감·테라조·벽 마감이 바탕 면과 같은 깊이일 때 일관되게 그려집니다. 재질 색, 이미지, UV, roughness, 투명도는 유지합니다. 유리는 깊이 보정 대상에서 제외합니다. depthTest/depthWrite는 계속 켭니다.

PC 카메라 near는 0.08m에서 0.12m로 조정해 깊이 정밀도를 개선했습니다. far=160m와 시야각, 눈높이, 이동 입력은 유지합니다. 렌더링 설정은 PC/VR이 공통 사용합니다. VR 추적 자세와 움직임은 보간하거나 바꾸지 않았습니다.

## 자연광 조정

| 설정 | 이전 | 수정 |
|---|---:|---:|

ACESFilmicToneMapping과 sRGB 출력은 유지합니다. 환경광 색은 약한 푸른 낮빛과 따뜻한 바닥 반사를 사용합니다. 텍스처 자체를 어둡게 보정하지 않았습니다. 이전/수정 조명을 동일한 모델·시점에서 비교한 화면은 lighting-before.png / lighting-after.png입니다.

## 검증과 범위

- 자동 검사 84개 통과: 기존 문·계단·충돌·PC/VR 모의 이동, 새 깊이 우선순위와 원본 색·UV·이미지 보존 검사 포함.
- GPU 합성 깊이 시험: 같은 위치의 두 면을 거리 1/2/10/40/100m, 앞뒤 그리기 순서로 렌더링하고 픽셀을 읽어 10/10 통과. 모든 GPU에서의 무결점 보장이나 학교 전체 모든 삼각형 쌍의 완전 탐색을 뜻하지 않습니다.
- 원본 GLB, 충돌 데이터, 문/계단 매니페스트는 1.3과 SHA-256이 같습니다(asset-hashes.json). 기존 충돌·이동·문 코드는 수정하지 않았습니다.
- 이 해결은 웹/실행 앱의 렌더링 설정에 적용됩니다. GLB만 다른 뷰어에서 열면 해당 뷰어의 깊이/조명 설정이 별도로 필요합니다.
- Quest 실기기와 macOS 앱 더블클릭은 직접 검증하지 못했습니다. 브라우저 화면 검수와 GPU 검사는 이 Mac 환경의 결과입니다.
