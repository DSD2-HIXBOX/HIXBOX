# 교실·복도 바닥 통일

## 기준 재질 분석

한국 교실의 `badak_standardSurface15_0`(glTF 노드 4), `standardSurface15` 재질을 기준으로 합니다.
원본 `standardSurface15_baseColor.jpeg`는 **512×512 갈색 목재 무늬**입니다.

- baseColorFactor: [0.4129536395, 0.4129536395, 0.4129536395, 1] (glTF 선형 값)
- metallicFactor: 0
- roughnessFactor: 0.8138173018
- specularFactor: 0.2354905533, 원본 KHR_materials_specular 유지
- doubleSided: true, 원본 유지
- KHR_texture_transform: U/V 각각 4회 반복, RepeatWrapping, mipmap 필터 유지

교실과 복도는 **동일한 Material·Texture 객체**를 공유합니다. 새 디자인·색상 보정용 재질·목재 이미지나
임의 normal map을 만들지 않았습니다. 복도의 기존 Floor normal/roughness 텍스처는 함께 섞지 않습니다.
따라서 양쪽의 거칠기·반사·기본 색상이 동일합니다.

## UV와 텍스처 크기·방향

교실은 폭 약 6.186m에 원본 텍스처를 4회 반복하므로 한 타일의 폭은 약 1.547m입니다.
길이 방향은 원본 UV 줄에 따라 일반 구간에서 한 타일 약 2.087m입니다.
목재 무늬의 방향과 U/V 변환, 반복 횟수는 교실에서 사용하던 값 그대로 유지합니다.

교실의 UV는 11개의 행으로 이루어지며 Z 간격이 모두 일정하지 않습니다. 단순히 두 바닥에 같은
텍스처를 넣거나 전체 복도 길이에 맞춰 늘리면 출입구에서 무늬가 어긋납니다.

`src/world/floorContinuity.js`는 교실 바닥의 오른쪽 경계에서 실제 (월드 X/Z, 원본 UV)를 읽습니다.
U는 교실 폭 기준으로 이어 쓰고 V는 원본 UV 행 사이를 보간합니다. 교실 밖에서는 끝 행의 밀도를
연장합니다. 복도 바닥을 이 행의 위치에서 세분화해 삼각형 내부에서도 동일한 보간이 이루어집니다.

- 복도 외곽과 면적 유지, 교실 바닥 geometry 불변.
- 복도 바닥은 6 → **50 삼각형**으로만 세분화(별도 메시/드로콜 추가 없음).
- UV는 0~1 바깥에서도 반복되어 긴 복도 전체에 교실과 동일한 밀도를 적용.
- 양쪽 문에서 실제 Raycaster 교차점의 UV를 비교해 무늬의 위상과 방향을 검증.
- 비스듬히 보는 바닥의 흐림을 줄이도록 기존 텍스처에 하드웨어 지원 범위 내 **최대 4× anisotropy** 적용.

원본 이미지가 512px이므로 원본 자체의 해상도 한계는 유지됩니다. 임의 확대 이미지나 생성형 텍스처로
교체하지 않았으며, 같은 거리에서 교실과 복도의 픽셀 밀도가 같도록 구성했습니다.

## 높이와 경계

교실 바닥은 원본 그대로 월드 Y=3.2m입니다. 복도 바닥의 FBX 변환에는 약 ±0.0000019m의 수직 오차와
원본 세 구간의 수 µm 크기 경계 오차가 있습니다. 런타임 복제 geometry에서만 다음을 정리했습니다.

- 모든 복도 바닥 정점을 월드 Y=3.2m 평면으로 정규화.
- 교실을 만나는 X 경계를 교실의 실제 오른쪽 경계에 맞춤.
- 복도 내부 세 구간의 미세한 경계 오차를 정리.
- 평면에 맞춰 법선을 통일하여 재질이 같아도 노멀 때문에 명암이 달라지는 현상 방지.

바닥을 복제해 겹쳐 깔거나 교실 바닥을 확대하지 않았습니다. 기존 복도 바닥을 런타임 geometry로
대체하고 원래 mesh 객체를 유지합니다. 출입구를 포함한 **충돌/보행 높이 3.2m, 경로, 문 충돌은 유지**합니다.
32비트 정점 오차는 테스트에서 1µm 이내로 관리하며 육안상 턱이나 빈틈이 없습니다.

## 조명과 Quest 비용

교실·복도에 같은 환경광과 햇빛을 사용하며 구역별 노출/색상 전환은 없습니다.
기존 반구광을 2 → 2.3, 햇빛 강도를 3.2 → 2.8로 조정해 공통 출입구의 명암 대비를 완화했습니다.
문틀이나 가구가 만드는 실제 그림자는 유지합니다. 추가 실시간 조명은 생성하지 않았습니다.

GLTFLoader의 `loadMaterial` 훅에서 복도 Floor 재질을 교실 재질로 대체하여, 사용하지 않을 원본
**2048px 바닥 텍스처 3개**를 다운로드·디코딩·GPU 업로드하지 않습니다.

- Floor_baseColor.png: 6,616,281 bytes
- Floor_metallicRoughness.png: 1,497,543 bytes
- Floor_normal.png: 4,054,179 bytes
- 합계 **12,168,003 bytes (약 11.60MiB)**의 이미지 요청 생략

같은 512px 교실 텍스처를 공유하고 바닥 draw call 수를 늘리지 않습니다. 실제 Quest 프레임률은 기기
검증이 필요합니다. GPU 메모리 절감량을 실측한 것은 아닙니다.

## 원본 보존과 재현

`public/models/classroom/`, `public/models/corridor/original/`, 기존 연결용 glTF/bin 파일을 수정하지 않습니다.
모델 로딩 후 `floorContinuity.js`가 복도 바닥의 런타임 geometry·UV·재질을 적용합니다.
`npm run prepare:corridor`로 연결용 모델을 재생성해도 바닥 통일은 다시 적용됩니다.

```sh
npm test
npm run build
npm run dev
```

검증: 교실 geometry 불변, 동일 재질 객체 공유, 복도 면적·외곽 유지, 두 출입구 UV/높이 연속성,
평면 법선 일치, 실제 GLTFLoader의 불필요 바닥 이미지 요청 생략, 기존 이동·문·숙이기 회귀 테스트.
브라우저에서도 기존 문을 열어 교실과 복도에 같은 목재 무늬가 이어지는 것을 확인했습니다.
