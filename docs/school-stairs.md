# School_[stairs] 추가

## 보존 범위

교실·복도 모델 파일, 현재 바닥 통일, 문, 텍스처 및 배치를 수정하지 않았습니다.
`docs/before-stairs-model-hashes.json`에 기존 모델 파일 44개의 SHA-256을 저장했고 테스트에서 일치를 확인합니다.
기존 복도 원본 계단과 현재 운동장까지 이어지는 임시 대피 경로도 그대로 유지합니다.

새 계단실은 **복도 +Z 끝 계단참의 오른쪽 출입구**로 연결합니다.
복도에서 직진해 끝 계단참에 들어선 뒤, 오른쪽에 추가된 기존 모델의 개구부로 진입하세요.
계단참 근처에서는 PC/VR 화면에 `오른쪽 출입구 → 추가 계단실` 안내가 표시됩니다.
계단실 안에서 왼쪽 하행 계단을 내려가 중간 계단참에서 돌아서면 아래층으로 도착합니다.
원래 직진 방향의 대피 계단과는 별도의 경로입니다.

## 추가 파일

제공된 `school_stairs.zip`에서 다음 세 파일만 추출했습니다(합계 2,141,400 bytes, 약 2.04MiB).

- `public/models/stairs/scene.gltf`
- `public/models/stairs/scene.bin`
- `public/models/stairs/license.txt`

모델에는 외부 이미지나 텍스처 의존성이 없습니다. 원본 PBR 재질 8개(벽·바닥·금속·유리 등)를 유지합니다.
불필요한 압축파일·이미지·기존 모델의 복사본·별도 파생 모델을 프로젝트에 넣지 않았습니다.
원본 zip과 Downloads 폴더는 수정하지 않았습니다.

## 구조·크기와 연결

원본은 244개 노드, 112개 메시, 47,636 삼각형이며 여러 층의 계단실이 포함되어 있습니다.
원래 좌표는 X 약 90.504~94.836, Y 약 -4.966~8.805, Z 약 -20.861~-9.960으로 원점에서 떨어져 있습니다.
이를 정규화해 기존 끝 계단참 오른쪽에 배치했습니다. 모델의 기존 출입구가 열려 있어 벽 절개는 필요하지 않습니다.
다만 입구의 사용하지 않는 폭은 같은 계단 모델의 벽 재질로 짧은 마감 벽을 두어 보호했습니다.
이 마감은 새 계단 쪽에만 있으며 기존 모델의 벽을 수정하거나 출입구를 겹쳐 설치하지 않습니다.

- 상부 바닥: 기존 복도와 같은 **Y=3.2m**.
- 하부 바닥: **Y=0m**.
- 원본 층간 높이 4.4m를 현재 3.2m에 맞추기 위해 수직 배율 **3.2/4.4 ≈ 0.7273** 적용.
- 수평 크기는 유지: 계단실 약 4.33m 폭, 약 10.90m 깊이. 디딤판 깊이 약 25cm 유지.
- 단 높이는 원본 20cm → 약 14.5cm로 보정됩니다.
- 원본 전체 높이에는 추가 상층 구조가 포함됩니다. 이번 보행 경로는 연결층 → 중간참 → 아래층과 왕복입니다.
- 기존 계단참과 새 입구의 바닥은 옆면에서 맞닿으며 시각적 바닥을 겹쳐 깔지 않았습니다.
- 원본 수치 오차 때문에 경계에 발이 걸리지 않도록 보행면에만 1mm 접합 허용값을 적용합니다.

`src/world/schoolStairs.js`에 배치, 하행 경로, 충돌과 배칭이 분리되어 있습니다.
`src/world/loadEnvironment.js`에서 기존 연결 공간 로딩을 끝낸 다음 새 계단 모델만 추가합니다.
교실·복도 생성 코드의 배치·재질·충돌 설정은 바꾸지 않았습니다.

## PC / Meta Quest 이동

- PC: 기존 **WASD**와 마우스 조작 그대로 사용합니다.
- Quest: 기존 **왼쪽 스틱 이동**, 오른쪽 스틱 스냅 턴과 헤드 추적을 유지합니다.
- 눈높이를 강제로 흔들거나 흔들림 애니메이션을 넣지 않았습니다.
- 시각적 단차는 원본 모델을 그대로 렌더링하고, 이동 높이는 그 위의 연속 경사면을 따라 바뀝니다.
- 계단참과 두 경사면의 높이를 연속으로 이어서 한 단씩 눈높이가 튀는 현상을 줄였습니다.
- 벽·천장·중앙 난간·창문 프레임은 원본 삼각형 충돌을 적용합니다.
- 디딤판과 금속 코의 미세한 돌출은 개별 몸 충돌 대신 연속 보행면으로 처리합니다.
- 중앙 틈과 바닥 밖에는 보행면을 만들지 않아 임의로 공중을 걷거나 다른 층으로 떨어지지 않습니다.

VR에서는 rig의 바닥 높이만 공통 보행 시스템으로 변경하며 카메라 회전/헤드셋 자세를 강제로 변경하지 않습니다.
실제 Quest의 이동감·프레임률은 연결된 기기가 없어 실기 검증이 남아 있습니다.

## 최적화

새 모델만 재질별로 병합해 **112개 메시 → 8개 정적 렌더 배치**로 줄였습니다.
원본 재질 색상·금속성·거칠기·유리 설정은 유지하고, 이미지 맵이 없는 모델이므로 사용하지 않는 UV/탄젠트만 배치에서 제외합니다.
기존 교실·복도는 병합하거나 다시 복사하지 않습니다. 새 마감 벽 1개가 별도로 있습니다.
새 동적 조명이나 큰 텍스처를 추가하지 않았습니다.

## 검증

```sh
npm test
npm run build
npm run dev
```

계단 테스트는 기존 자산 해시, 입구 높이, 두 계단의 연속 하강·상승, 벽·난간 충돌,
하부 바닥 도달과 기존 운동장 경로 유지를 확인합니다. 계단 이동은 PC·VR이 같은 CollisionWorld를 사용합니다.
노드별 바운딩 박스와 재질 정보는 `docs/stairs-node-analysis.json`에 있습니다.
