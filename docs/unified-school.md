# 같은 제작자 학교 통합 기록

## 원본 분석과 연결 판단

네 패키지의 asset author URL은 `sketchfab.com/yuuuusukeeee`로 같습니다. entrance의 표시명은 Comicaroid입니다. 원본 파일은 Downloads에 그대로 보존합니다. 이전 프로젝트는 교체 전에 `backups/pre-unified-20261027-1838.tar.gz`에 보관했으며 이전 한국 교실과 일본 복도 파일도 삭제하지 않았습니다.

좌표는 미터 단위이지만 각 패키지의 원점은 다릅니다. 아래는 원본 바닥/입구 기준입니다.

| 모델 | 원본 기준 | 연결 판단 |
|---|---|---|
| 교실 | X -100.69…-92.39, Z -10…0.16, 바닥 Y 0 | 약 8.3 × 10.16m. 문은 X -100.6 벽에 두 곳 |
| 복도 | 교실 자리 X 61.433…69.733, Z -10…0.16 | 교실 자리와 동일 규격의 빈 외피가 포함됨. 교실을 X +162.1233m 이동하면 문 위치가 일치 |
| 계단 | 입구 Z -9.96, 바닥 Y .005 | 두 하행 구간이 각각 2.2m, 층간 4.4m. 회전·평행이동으로 복도 +Z 끝에 정합 가능 |
| 출입구 | 중앙 통로 X -2…2, Z -7.15…19.15, 바닥 Y -.05 | 길이 방향 끝을 아래층 계단참에 연결 가능. 원본 끝면은 막혀 있어 개구부가 필요 |

원본 그대로 0,0,0에 겹쳐 두면 연결되지 않습니다. 실제 배치 행렬은 `unified-build-report.json`에 기록했습니다. 최종 교실/복도 바닥은 Y 4.4m, 계단 아래층은 Y 0m입니다. 계단의 비율은 변경하지 않았습니다.

## 적용한 연결 수정

1. 복도에 포함된 빈 교실 외피(노드 53/58/64/66)와 공통 벽에 중복된 문/문틀/유리를 제외했습니다. 교실 원본의 공통 벽과 두 문을 한 번만 사용합니다. 다른 교실의 반복 파사드는 유지합니다.
2. 문은 교실 원본 노드 30/32/34/36의 패널, 41/43/53/55의 프레임, 62/64/66/68의 유리를 묶었습니다. 앞/뒤 두 출입문 각각 두 패널이 0.76m씩 반대 방향으로 이동합니다. 재질·형태·UV·크기를 유지합니다.
3. 교실 바닥의 공통 벽 쪽 끝만 5mm 정합했습니다. 복도 바닥 위로 교실 바닥을 확대해서 덮지 않습니다. 복도 자체의 기존 바닥 재질과 구조를 사용합니다.
4. 복도 +Z 끝 벽을 실제로 절개하여 계단 입구를 엽니다. 월드 절개 범위는 X -6.95…-3.05, Y 4.401…6.9, Z 46.47…46.70입니다. 문을 새로 배치하지 않습니다. 계단의 기존 입구를 통과합니다.
5. 1층 현관 북쪽 끝면의 통로 부분을 X -6.95…-3.05, Y .001…2.5, Z 49.15…49.3 범위에서 실제 절개했습니다. 계단 하부 접합 범위도 검사/절개하도록 스크립트에 명시했으나, 원본의 기존 개구부가 있어 삼각형 수는 그대로입니다.
6. 절개 시 모든 정점 속성을 보간합니다. 바닥·천장·창문 등 통로 범위 밖은 보존합니다. 연결부 보행 판정의 1–6mm 허용 구간은 수출 오차만 보완하며 가상의 긴 다리나 화면 전환을 사용하지 않습니다.

`prepare-unified-school.mjs`가 별도 파생본을 만듭니다. Blender 없이 정점/삼각형 절개가 가능하므로 원본 편집은 하지 않았습니다. 원본 자체가 단순한 학교 에셋 스타일이며 포토리얼리스틱한 새 디자인으로 바꾸지는 않았습니다.

## 이동과 충돌

- PC/XR 모두 동일한 `CollisionWorld`를 사용합니다.
- 바닥은 원본 상향 삼각형의 실제 윤곽을 사용합니다. 복도의 넓은 bounding box 전체를 바닥으로 간주하지 않습니다. 교단과 현관의 낮은 신발장 구역도 별도 보행면입니다.
- 계단은 보이는 디딤판 위에 연속 램프 보행면을 사용합니다. 층간 높이 4.4m를 유지하며 임의의 카메라 흔들림을 넣지 않습니다.
- 문 충돌 상자는 패널 위치를 따라 이동합니다. 닫힌 문은 자동으로 열리지 않습니다. 닫히는 중 몸이 있으면 다시 열고, 출입구 안에서 닫기 요청은 거절합니다.
- 벽·창·책상·의자·난간은 1m 공간 그리드에 분류한 정적 삼각형으로 충돌합니다. 고밀도 곡면은 8mm 오차 이내의 별도 간략 인덱스를 사용합니다. 보이는 가구를 큰 단일 상자로 막지 않아서 책상 아래 빈 공간이 남습니다.
- 숙이기 신체 높이 .46m / 눈높이 .40m. 서기 높이 1.7m / 눈높이 1.65m. 상판 아래에서 일어서기를 거절합니다.

원본 계단에 보이는 위층 방향은 외형으로 남아 있으나 현재 보행면은 요청한 2층→1층 경로에 한정합니다. 다른 복도 문 뒤의 새 교실이나 운동장은 추가하지 않았습니다.

## 최적화

- 교실: 5,948,532 → 238,291 삼각형, 원본 217,430,456바이트 버퍼 → 9,138,564바이트. 3mm 위치 오차를 제한한 곡면 가구 감량이며 문과 저밀도 건축 요소는 유지합니다.
- 네 모델을 URL별로 한 번 요청하고 캐시합니다. 씬 인스턴스는 분리하며 동일 geometry/material 자원을 공유합니다.
- 반복 정적 물체는 재질과 8m 공간 셀별로 묶어 draw call을 줄입니다. 보이지 않는 다른 층의 내부를 층 높이에 따라 제외합니다. 가까운 문 후보가 없으면 전체 장면 상호작용 레이캐스트를 생략합니다.
- 원본 4K 텍스처는 별도 2K 파생본으로 만들고, Quest에서 1K로 더 낮춰 GPU 메모리를 줄입니다. 원본 색/무늬/UV를 유지합니다. 새 바닥 이미지는 생성하지 않았습니다.
- 원본 재질을 바꾸지 않고 저해상도 PMREM 실내 환경광을 공유하여 금속성 재질의 검은 반사를 보완합니다. PC 최대 DPR 1.5, Quest 프레임버퍼 배율 .9, Quest 실시간 그림자 비활성화. 모델별 다수의 동적 조명은 추가하지 않습니다.
- 배포본에는 unified 모델만 포함합니다. 백업/기존 모델/개발 검증 페이지는 제외합니다.

## 검증 범위

새 통합 테스트는 시작 위치, 양쪽 문 각각의 닫힘/열림/통과, 공통 경로 전체 왕복, 계단 높이 변화, 벽/난간, 상판 아래 기립 제한, 양쪽에서 E/VR 공용 대상 선택, 시작 위치에서 뒷문 접근을 확인합니다. 이전 모델 파일의 SHA-256 보존 검사도 유지했습니다.

개발 브라우저에서 실제 텍스처 로딩, 복도–계단 개구부, 하행 계단, 현관을 시각적으로 확인했습니다. WebXR 코드와 컨트롤러 이벤트 연결은 유지되지만 실제 Meta Quest 기기 FPS·입력·멀미감은 이 컴퓨터에서 측정하지 않았습니다. 프레임레이트를 보장하는 수치는 제시하지 않습니다.
